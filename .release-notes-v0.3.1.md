Dockerfile-only patch. Python package contents are unchanged from
[v0.3.0](https://github.com/data2intelligence/SecActpy/releases/tag/v0.3.0).

## Fixed

- **Docker `with-r` / `gpu-with-r` images**: pin `BiRewire 3.40.0` from the Bioconductor 3.21 archive.

  `BiRewire` was deprecated in Bioconductor 3.22 and removed entirely in 3.23. The R 4.6 base image now ships Bioc 3.23, so `BiocManager::install("BiRewire")` returned `package 'BiRewire' is not available for Bioconductor version '3.23'` and the R-image builds aborted at the R-dependency verification step.

  `SpaCET 1.4.0` (bundled in the R-enabled images) still hard-imports `BiRewire` (`Imports: BiRewire`), so dropping it isn't an option. The Dockerfile now installs `BiRewire 3.40.0` (last release, 2025-04-15) from `bioconductor.org/packages/3.21/bioc/src/contrib/` via `remotes::install_url()`, with CRAN deps (`igraph`, `slam`, `Rtsne`, `Matrix`) resolving from RSPM. `BiRewire` was also removed from the Bioc 3.23 bulk-install list (where it could no longer succeed).

  Verified end-to-end in workflow run [25853557199](https://github.com/data2intelligence/SecActpy/actions/runs/25853557199):

  ```
  Installing BiRewire 3.40.0 from Bioc 3.21 archive...
  BiRewire 3.40.0 OK
  All 38 required R packages verified OK
  SpaCET 1.4.0 OK
  ```

  Successful on amd64 and arm64 R variants + the GPU+R variant.

## Affected images

- `data2intelligence/secactpy:0.3.1-with-r` / `:with-r` (CPU + R, amd64 + arm64)
- `data2intelligence/secactpy:0.3.1-gpu-with-r` / `:gpu-with-r` (GPU + R, amd64)

CPU/GPU Python-only images (`:0.3.1` / `:0.3.1-gpu`) and the PyPI wheel are unaffected — they did not depend on the broken Bioconductor path.
